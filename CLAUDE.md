# Whose Song Is It? — notes for Claude

Unofficial companion game for Greg's Music League: players guess who submitted each song in a round, then the host reveals the real submitters and the game scores it.

- Live site: https://whose-song-is-it.netlify.app (Netlify project owned by Greg, deploys automatically from `main` of gregdgardner/whose-song-is-it).
- `public/index.html` is the whole front end (no build step). Styling: charcoal app bar with a purple edge, Poppins + Archivo, light theme only. Keep it related to Music League but not a copy; keep the "unofficial, not affiliated" footer.
- `netlify/functions/api.mjs` is the server (Netlify Functions v2 + Netlify Blobs store "game"). Other players' picks are only returned for revealed rounds; answers are only stored at reveal.
- Players pick a name with no login and set a 4-digit PIN; other devices join that name with the PIN (claims hold several token hashes; 5 wrong PINs lock it for 15 minutes). Names claimed before PINs existed are prompted to add one. The host can unlock a name on the Host tab (clears the PIN). The host code is set by whoever first enters one on the Host tab.
- Each pick can carry an optional note (max 200 chars), private until the reveal like picks, then shown under the song.
- Blobs reads can lag right after a write, so the page keeps the chosen name and picks locally and never clears them just because the server hasn't caught up.
- Rounds have `perPlayer`: the most times one name can be picked (0 = no limit). New rounds default to ceil(songs ÷ players); the pick menu disables used-up names and `/api/guess` rejects picks over the limit.
- Players press Submit to send picks; they can resubmit until the reveal or the guessing deadline, whichever comes first.
- Guessing deadline: rounds have `guessDeadline` (ISO UTC, or null for no deadline) and `closedAt` (set when the host closes guessing by hand). It should always equal Music League's voting due time, because ML shows who submitted each song once voting ends. The automation that opens a round sets it from ML; the Host tab's "Guessing due by" field (entered and shown in Pacific time) is a manual override, with "Close guessing now" / "Reopen guessing" buttons. `/api/guess` rejects with 409 after the deadline or when closed; reveal and scoring are unaffected. Players see "Guessing due by Friday, Nov 20, 9:00 PM PT" on the open round and a "Guessing closed" state after. Rounds stored before this (no fields) behave as before. `/api/state` also returns the server's `now` so the page locks on time even if a phone clock is off.
- Host API (for automations): every `/api/host/*` call is a JSON POST with `code` set to that league site's host code (the same code typed on the Host tab). Deadlines accept an ISO time with a zone (`2026-11-20T21:00:00-08:00`, `...Z`), epoch milliseconds, or a zone-less `2026-11-20T21:00`, which is read as Pacific time; anything else gets a 400.
  - Create a round with its deadline: `POST /api/host/round` `{code, round: {id, title, prompt, playlist, players[], songs[{id,title,artist}], perPlayer, status:"open", guessDeadline}}`. Re-posting a round without a `guessDeadline` key keeps the stored one; `null` clears it.
  - Move the deadline when ML's due time shifts, or close/reopen: `POST /api/host/deadline` `{code, roundId | playlist, guessDeadline?, closed?}`. `playlist` matches the round's playlist link (query string ignored). Only the sent fields change. The response is `{ok, round}`, where `round` includes `guessDeadlineText` (PT) and `guessingOpen`.
  - Example: `curl -X POST https://whose-song-tkes.netlify.app/api/host/deadline -H 'content-type: application/json' -d '{"code":"<host code>","playlist":"https://open.spotify.com/playlist/<id>","guessDeadline":"2026-11-20T21:00:00-08:00"}'`
- Scoring: 1 point per correct match, +3 for a perfect round; a player's own song never counts. The Leaderboard tab shows a "Round results" table for one revealed round (newest by default, with a picker for earlier ones) above the cumulative "Overall standings" across all revealed rounds. Scoring runs in the page (`scoreFor`), not the server.
- Guess webhook (optional, per site): if both `GUESS_WEBHOOK_URL` and `GUESS_WEBHOOK_AUTH` env vars are set, a saved guess POSTs `{event:"guess_submitted", site, roundId, roundTitle, player, songsGuessed, firstSubmit, submittedCount, playerCount, guessDeadline, timestamp}` with `Authorization: <GUESS_WEBHOOK_AUTH>` (3 s timeout, failures ignored). No picks, notes, or answers are sent.
- Every push deploys every league site and uses Netlify credits (the team ran out once in Nov 2026 and Greg upgraded). Bundle changes into few pushes.
- Claude can't reach netlify.app or the Netlify API from its sandbox. To add a round for Greg, append it to `netlify/functions/imports.mjs` (id, site, title, prompt, playlist, players, songs[{id,title,artist}], createdAt) and push. `site` is the Netlify project name of the league it belongs to (default `whose-song-is-it`); each league is its own Netlify site deployed from this same repo, with its own data and host code. The round it is added once on the next page load and stays deleted if the host deletes it.
- Host tab fills a new round's songs from the pasted Spotify link: `/api/host/playlist` fetches `open.spotify.com/embed/playlist/<id>` server-side and `playlistFromEmbed` pulls the longest track-like list out of its JSON script tags (layout not verified against live Spotify from the sandbox; if it breaks, check that first). Songs can also come from submissions.csv. Both shuffle the order.
- Spotify playlist tracks can be read with WebFetch on `https://open.spotify.com/embed/playlist/<id>`.
- Player names come from Music League's `competitors.csv` (ID,Name); duplicate names get " (2)". The Host tab can also load that CSV directly.
- Reveal answers: the Host tab's "Fill from Music League export" takes submissions.csv + competitors.csv (+ rounds.csv, which picks the round by playlist link) and fills the submitter dropdowns by matching song titles. The export is per league, so check rounds.csv to see which league it came from.
